# Технічний дизайн

Код пише ШІ, тому архітектура оптимізована під **текстові файли**: логіка — у C++,
дані — у CSV/JSON, які імпортуються в DataTable. Blueprint'и (бінарні `.uasset`) —
лише тонкі нащадки C++-класів для призначення мешів, матеріалів і ефектів.

## Стек

| Що | Рішення |
|---|---|
| Рушій | Unreal Engine 5.8 |
| Мова | C++ (основна), Blueprint — лише налаштування ассетів |
| Навички та характеристики | **Gameplay Ability System (GAS)** |
| Ввід | Enhanced Input |
| ШІ ворогів | StateTree (або Behavior Tree) + EQS для вибору позицій |
| Навігація | NavMesh з runtime-генерацією (Dynamic), бо рівні процедурні |
| UI | UMG + CommonUI, логіка віджетів у C++ (ViewModel/MVVM-плагін) |
| Дані | DataTable (з CSV/JSON у `Data/`), Primary Data Assets |
| Ефекти | Niagara (заглушки) |
| Збереження | `USaveGame` + серіалізація у слоти |
| Локалізація | String Tables (CSV), Localization Dashboard, культури `uk` та `en` |
| Контроль версій | Git + Git LFS для `.uasset`/`.umap` |

    ├── Kossaks.uproject

## Ключові системи

### Персонаж та класи
- `AKosCharacterBase` (ASC, AttributeSet) → `AKosPlayerCharacter`, `AKosEnemyCharacter`.
- Клас гравця — `UKosClassDefinition` (Primary Data Asset): ресурс, стартові навички, дерево навичок, дозволені типи зброї. Нові класи додаються даними, а не новим кодом персонажа.
- Керування: `AKosPlayerController` — рух WASD відносно камери, поворот до точки під курсором (trace по площині землі).

### GAS
- AttributeSets: `Health`, `Resource`, `Armor`, `Strength/Dexterity/Intelligence/Willpower`, опори, крит, швидкість атаки, швидкість руху, скорочення КД.
- Шкода — через `UGameplayEffectExecutionCalculation` (одне місце для формули).
- Кожна навичка — `UKosGameplayAbility` з параметрами з DataTable (шкода, вартість, КД, радіус). Ранги/модифікації дерева — теги та множники.
- Стани (горіння, переляк, оглушення) — GameplayEffects з тегами `State.*`.

### Формула шкоди (стартова, у даних)
```
Шкода = БазаЗброї × КоефНавички × (1 + Σ%Шкоди) × (1 + ОснАтрибут/100)
        × КритМножник × (1 − Опір) × (1 − Броня/(Броня + 50·РівеньАтакуючого))
```

### Предмети
- `FKosItemInstance` (struct, серіалізується): базовий тип, рідкісність, Item Power, масив афіксів (ID + значення), аспект, рівень покращення.
- Генерація: таблиця луту → базовий предмет → рідкісність → афікси з пулу для слоту з вагами → значення в діапазоні за Item Power.
- Детермінованість: генерація з seed для відтворюваності багів.

### Процедурна генерація
- **Тайловий підхід:** набір модульних «кімнат»/ділянок (ручні Level Instance або актори-префаби) з точками з'єднання. Генератор будує граф (головний шлях + відгалуження), розміщує тайли, перевіряє перетини.
- Відкриті зони (степ) — сітка ділянок + розкидання декору/перешкод за шумом.
- Після розміщення — перебудова NavMesh, розстановка точок спавну груп, скринь, входу до підземелля.
- Seed зберігається в стані сесії й виводиться в дебаг-меню.

### Збереження
- `UKosSaveGame`: персонаж, інвентар, спорядження, дерево, прогрес кампанії, складність, прапорець хардкору.
- Спільна скриня й Кодекс — окремий файл акаунта.
- Версіонування структури збереження (поле `SaveVersion`) для міграцій.

## Правила для коду (для ШІ)

- Префікс класів проєкту: `Kos` (`AKosEnemyCharacter`, `UKosLootSubsystem`).
- Жодних магічних чисел у коді балансу — усе в DataTable.
- Жодного тексту для гравця в коді — лише `FText` з String Table.
- Нова функціональність — спочатку C++-клас з `UPROPERTY(EditDefaultsOnly)` для ассетів, потім тонкий Blueprint-нащадок.
- Дебаг: консольні команди (`Kos.GiveItem`, `Kos.SetLevel`, `Kos.Regenerate <seed>`, `Kos.GodMode`).
- Автотести: Automation Tests для генерації луту, формули шкоди, генератора рівнів (перевірка зв'язності).

## Обмеження середовища

ШІ-сесія в хмарі не може запустити чи скомпілювати Unreal Engine. Тому:
- компіляція й запуск — на ПК розробника; помилки компіляції/логи передаються ШІ;
- чисті логіка й дані (формули, генерація луту, генератор графа рівня) бажано писати так,
  щоб їх можна було тестувати без запуску рушія.
